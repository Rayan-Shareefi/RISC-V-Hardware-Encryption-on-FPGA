Small CPU vs fast CPU - same crypto hardware, 1000 runs each, Cmod A7-35T @ 12 MHz
(re-measured 2026-10-08 after Step C: long messages + RFC 8439 ChaCha20-Poly1305, fast Keccak software)
Small CPU = final design (demo/neorv32_crypto.bit): serial multiplier + serial shifter (lightweight).
Fast CPU  = demo/neorv32_crypto_fastcpu.bit: CPU_FAST_MUL_EN (DSP multiplier) + CPU_FAST_SHIFT_EN
            (barrel shifter). The divider stays serial in both. Same C programs (make APP=demo_... clean exe).

Cycles per run (time = cycles / 12 MHz)            Small CPU                Fast CPU
                                                   SW      HW    Speedup    SW      HW    Speedup
ChaCha20 (64-byte block)                           20101   285    70.3x     8565    285    30.0x
Poly1305 (64-byte message)                         13323   365    36.4x     4367    365    11.9x
ChaCha20-Poly1305, RFC 8439 (64 B + 12 B AAD)      58197   2270   25.6x     22207   2236    9.9x
Keccak-256 (64-byte message)                       130461  261   498.5x     79665   261   304.4x

The hardware cycles do not change (the accelerator does the work); only the software gets faster.
Even against the faster CPU, the accelerator is about 10x to 300x faster.
(History: before Step C the 3rd row was "Encrypt + MAC" with a separate Poly1305 key:
 52.9x small / 20.4x fast; Keccak with the old slow software: 1174.7x / 736.8x.)
